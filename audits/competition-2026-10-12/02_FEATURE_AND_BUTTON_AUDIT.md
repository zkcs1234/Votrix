## How to read the inventory

The inventory follows the mounted routes, handlers, service calls, backend branches, and persistence contracts. A UI element's presence is not evidence that its operation succeeds. **Partially working** means a trace exists and, where cited, a mocked component test exercises the frontend boundary; the real authenticated browser-to-database operation has not been verified. **Broken** identifies a source-demonstrated incompatible contract or missing update path. **Missing** identifies an absent control/workflow, without assuming it is an approved requirement. **Cannot verify** identifies an external/runtime dependency or an unexercised ambiguous path.

Frontend suite execution and its exact result are recorded in [07_END_TO_END_TEST_PLAN.md](07_END_TO_END_TEST_PLAN.md) and the `_evidence` logs. A passing mocked test does not establish deployed migrations, socket delivery, email arrival, or complete real-browser behavior. No row below is an unconditional production-readiness claim.

Path prefixes in this report are exact repository directories:

## 8. Disconnected and misleading controls requiring priority attention

The following are source-evidenced defects, not claims from screenshots:

1. **Modern scheduled Unpublish to draft is incompatible with the backend.** The visible action requests ordinary unpublish, but acknowledged rules require an approved amendment. The page also promises post-publish judge registration that its modern roster does not support.
2. **Modern progress-grid unlock requests omit mandatory reason and confirmation.** The separate workflow-panel correction has those fields, so two controls for the same apparent user intent behave differently.
3. **Bulk judge assignment discards request failures.** `Promise.allSettled` resolves even if every request rejects; the component's catch cannot report those rejections.
4. **Reviewer and Tabulation screens do not update when the other account acts.** Neither subscribes or polls; they can stall an otherwise connected verify/finalize sequence until manual reload/navigation.
5. **Active judges lack a polling fallback when sockets fail.** Their waiting poll stops precisely when scoring becomes active. A stale open sheet remains until an applicable message/reconnect/manual reload.
6. **Unfiltered Rankings ignores invalidation-only events.** Its handler requires a supplied rankings payload; receiving an event name alone does not refetch.
7. **Published Divisions and hidden Categories still expose setup edits.** Server frozen guards protect data, but the UI presents changes that cannot succeed and several handlers omit catches.
8. **Initial Live Control errors can look like “No session.”** Error suppression creates a Start action despite inability to read the current authoritative session.
9. **Manual result inputs are not scoped to the selected round's eligible field.** They enumerate all event contestants; the backend calculation validates the selected field. A Final with a smaller qualified roster requires avoiding visible unrelated inputs.
10. **Reports can render missing values as zero and make failed refreshes look current.** Formatting and last-updated semantics require consistency with snapshot nulls and successful reads.
